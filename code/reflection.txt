one_package.py, process_file.py, and process_files.py all use the same guard pattern: check if there's a return value from the widget (package_data, uploaded_file) before doing anything with it, since the script reruns top to bottom every time someone types or clicks. I broke this a few times without realizing it, by writing code that looked indented under the if but wasn't actually inside it in the file, so the app crashed on the very first run before I had typed or uploaded anything.

process_file.py introduced decoding bytes to text before splitting into lines, since an uploaded file comes as bytes, not a string. process_files.py was the hardest because of session state. I learned that a normal variable resets to its starting value on every rerun, so files_processed and packages_processed had to be in st.session_state instead, initialised only once. I also had a bug where I put the two st.metric cards before the code that ran on the click and actually updated the counts, so the page always showed the old numbers one rerun behind. Moving the processing above the metrics fixed it. Next time I want to think through the order things get shown on the page before I write them, instead of fixing it after a test tells me the numbers are wrong.
